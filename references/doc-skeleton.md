# 文档骨架（固定，不许改结构）

飞书文档一章一节的名称、编号、层级都不能动，只换内容。用户拿到的四篇稿子必须能像流水线一样对齐。

## 一、文档标题与命名

- 标题：`0X_选题名_全量文案`，`0X` 接续目标文件夹里已有编号（示例为 `01_全量文案示例`）
- 首行 `<h1>` 与标题同构：`0X_全量文案`
- 编号用手写编号（`01｜`、`一、`、`卡01｜`），**不要加 `seq="auto"`**，避免和手写编号叠加

## 四、三个不要

- **不要**把画板清单做成内嵌 sheet；用文档表格即可，字段一致。
- **不要**用 `<img>` 贴截图代替画板：结构关系要能读出一二三条，不是一张氛围图。
- **不要**在文档里放内部思考、备选废稿、字数统计；只留最终稿。

## 五、画板怎么落地（公众号每节一张）

1. 先写正文，再抽结构：正文定稿后，用一句话写出这一节"要让人看懂什么关系"，这句话就是图题。
2. 生成 SVG：**1600×1600 正方形**（飞书画板画布 1:1，16:9 内容会上下留白），深藏蓝 `#2A5D8F`、浅底 `#F4F7FA`、细线 `#DEE3E8`；三层以内，节点不超过 6 个。
3. 写入文档：生成在工作目录，XML 里用 `<whiteboard type="svg" path="@./wb-0X.svg"/>`，位置紧跟在对应 `<h4>` 的正文 `<p>` 之后。
4. 飞书里是真正可再编辑的画板，不是截图；写入前按 `lark-doc` 的 XML 参考重读画板写法，样品与配色参考 `lark-whiteboard`、`fg-beautiful-feishu-whiteboard`。
5. 校验：`scripts/validate_pack.py` 会检查 `wechat.boards` 的数量（6–8 张）、每张的文件是否存在、结论条是否超 12 字。

品牌色是唯一的例外：用户指定别的品牌色时按用户口径，但一张图内不超过三色。
